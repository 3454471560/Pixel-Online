# <img src="./icon/Tree.png" alt="Online" style="zoom:30%;" /> Pixel Online像素联机游戏

[![Language](https://img.shields.io/badge/Language-C%2B%2B20-blue.svg)](https://en.cppreference.com/w/cpp/20) [![Platform](https://img.shields.io/badge/Platform-Windows-lightgrey.svg)]() [![Compiler](https://img.shields.io/badge/Compiler-MSVC%20v143%20(VS2022)-purple.svg)]() [![License](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)

**Pixel Online** 是一个基于 **C++20** 开发的**分层式2D网络游戏项目与运行时框架**。项目以「高内聚、低耦合」为核心设计原则，通过 客户端/服务端模块化引导、全局上下文、动态接口注入三层核心抽象，构建了涵盖渲染、物理、音频、资源、ECS、网络的完整游戏开发管线，实现了现代游戏的高性能与可扩展性设计。

---

## 🏗️ 架构设计 (Architecture)

Online 采用分层、模块化和数据驱动的架构，支持可插拔模块、热重载与工具流水线：

*   **Application**: 客户端(Client)、服务端(Server)，游戏/服务器的启动/关闭、模块注册与主循环，集中管理模块依赖与生命周期。

*   **Modules**: 渲染(Render)、物理(Physics)、窗口(Window)、输入(Input)、音频(Audio)、时间(Time)、脚本(Script)、游戏(Game)、网络(Net)等核心子系统均遵循统一生命周期契约，依托全局上下文与函数指针表实现动态注入。通过编译期宏完成客户端与服务端的代码级隔离，可按需裁剪渲染、音频等表现层模块，在保证双端逻辑同源的同时，最小化服务端运行时开销。
*   **Tools**: 数据与工具层，处理资产流水线与游戏周边工具，包含资源导入转换（Importer）、序列化/反序列化（Serialization）及编辑器支持与离线工具链（例如 Tile 编辑器、资源硬编码工具提供核心支撑。
*   **Core**: 基础核心层，提供单例模板、对象池、内存分配抽象（Core/Allocate）、状态标志、线程安全数据结构、线程/任务基础库等跨模块公共类型。
*   **Thirdparty**: 外部依赖库，包含渲染、物理、数学以及序列化工具。

## ✨ 核心特性 (Key Features)

- 🛠️**模块化引导 (Bootstrap System):** 统一的游戏启动与关闭流程，确保子系统按依赖顺序初始化。
- 🧵**异步日志系统 (Async Logging loop):** 基于线程接管的日志记录机制，确保磁盘 I/O 不影响主逻辑帧率。
- 📦**高效内存管理:** 内置对象池以及全局**mimalloc**内存分配，减少运行时内存碎片，多线程内存无锁分配。
- 🧬**渲染主线程分离 (Thread Separation):** 实现渲染线程与逻辑线程解耦，通过指令队列实现异步渲染。
- ⚡**全局事件系统 (Event System):** 基于消息总线的解耦通信机制，简化主线程模块间交互。
- ⌨️**输入系统 (Input System):** 支持状态轮询与事件回调，抽象了键盘、鼠标的底层输入。
- 🕒**高精度时间系统 (Time System):** 毫秒级 deltaTime 计算与全局时钟管理以及帧率限制。
- 📥**异步资源管理系统(Async Asset System):** 多线程分层加载 / 释放资源，主线程提交请求、任务线程加载 CPU 数据、渲染线程创建 GPU 资源，结合线程安全队列保障生命周期安全。
- 🔖**资源状态原子控制(Atomic State Flags):** CPU/GPU 双端原子标志位管控资源全生命周期，规避多线程竞态与访问异常。
- 🧩**线程池任务系统(Thread Pool):** 轻量级线程池实现任务异步调度与优先级管理，最大化多核 CPU 利用率，减少线程创建 / 销毁开销。
- 🔒**线程安全容器(Thread Safe Container):** 封装线程安全的队列、哈希表、双向表等容器，简化多线程场景下的并发编程。
- 🔗**线程封装 (Thread Wrapper):** 对象化封装 Windows 原生线程操作，提供类型安全接口，兼顾易用性与原生能力。
- 🎨**渲染命令系统 (Render Command System):** 渲染命令采用 POD 类型实现高效字节操作，通过 SortKey 排序保证渲染执行顺序与画面效果正确。
- 🎵**音频播放系统 (Audio Player System):** 实现优先级驱动的通道调度，帧级音效状态同步，支持2D空间化音效与分离式背景音乐 / 音效管理。
- 📜**自动合批系统 (Auto Batching System):** 基于渲染队列排序规整绘制指令，动态聚合相同纹理的渲染指令，减少频繁切换纹理，利用 SDL 延迟队列大幅削减 DrawCall，显著提升 CPU 提交效率与 GPU 吞吐量。
- 🔌 **动态接口注入系统 (Interface Injection System):** 构建以 **Context** 为核心的全局上下文环境，配合 **FuncTable**（函数指针映射表）实现逻辑单元的动态注入。子模块间不产生代码层面的强链接依赖，仅通过接口契约在运行时进行功能寻址与调用，显著提升了系统的灵活性与可扩展性。
- 🗃️ **多后端序列化系统 (Multi-Backend Serialization System):** 基于状态机式架构，抽象的序列化/反序列化上下文接口，内置 JSON/MsgPack 双后端，支持基础/GLM类型与嵌套结构，提供文件/字符串/字节流三种IO，统一数据持久与网络传输标准。
- 🎮**ENTT ECS 核心架构:** 基于ENTT构建**纯数据驱动**的底层核心框架。将游戏拆分为**实体 (Entity)**、**组件 (Component)**、**系统 (System)** 三层，组件连续内存布局与系统的缓存友好批量遍历。同时保留了传统`GameObject-Component`模式的易用性接口，兼顾极致性能与开发效率。
- 📋**脚本注入系统(Script Registration System):** 为所有挂载在 GameObject 的脚本开辟独立内存块存储脚本数据，配合函数指针存储生命周期方法，依托注册表统一注册脚本，由游戏对象管控脚本挂载、卸载与全周期回调，直接对接组件业务。
- 🌳**世界树场景系统（WorldTree System）**：基于双向链表构建无递归高效父子层级树，支持全链路序列化反序列化与独创跨组件引用自动修复以及脚本自动挂载，提供后台加载 / 自动切换 / 加载页过渡三级异步无缝切换。
- ⚙️**Box2D 物理模拟系统 (Physics Simulator):** 采用**预分配刚体池**与**帧级批量同步**机制，支持多形状碰撞体与分层碰撞过滤，内置传感器事件与射线/重叠检测，物理与ECS实体的无缝同步，保证模拟稳定与性能。
- 🗺️**瓦片地图 (Tilemap) 渲染与碰撞系统:** 支持多层瓦片地图的离屏渲染与碰撞检测。实现瓦片的**批量合批绘制**，动态根据瓦片信息生成物理碰撞体，支持**贪心矩形合并**大幅消减物理计算压力，以及瓦片地图数据的序列化加载。
- ✏️**瓦片地图编辑器 (Tilemap Editor):** 与引擎瓦片地图系统深度耦合的专业可视化编辑工具。基于ImGui构建高性能UI。采用 CSV 格式持久化，完整文件生命周期管理，未保存变更检测与崩溃安全退出机制。多图层独立编辑与显隐控制，放置擦除双模式，多级缩放、网格辅助对齐与实时预览。
- 🔤**文本渲染系统（Text Rendering system）**：基于字体图集纹理的高性能文字渲染方案，支持排版计算与逐字符提交。文本组件支持多字体、锚点对齐、字间距、动态换行、宽度限制、层级排序等布局特性。
- 🎛️**UI 脚本系统**：控件由`Sprite`+`Text`+`Script`组合而成，无传统重型 UI 树。按钮支持纹理切换/颜色叠加双模式，输入框内置IME深度集成与码点级精确光标，通过注册lambda回调，即插即用。
- 📡**网络通信系统 (Network Transport Layer):** 基于ENet构建的异步C/S通信架构，通过独立网络线程与线程安全消息队列实现 IO 全链路解耦，彻底消除网络操作对主逻辑帧率的阻塞。提供可靠有序与不可靠双通道适配不同业务优先级。
- 🌐**网络状态同步系统 (Network State Sync System):** 采用服务端权威物理模拟架构，形成玩家输入上行、实体状态下行、世界快照全量兜底的三级同步机制。客户端结合本地预测与平滑插值修正，严格保证多端逻辑一致性的基础上，实现接近单机的零延迟操作手感。

## 🚀 快速开始 (Getting Started)

### 🧰环境依赖

*   **操作系统:** Windows 10/11
*   **IDE:** Visual Studio 2022 (至少支持 MSVC v143)
*   **SDK:** Windows 10 SDK (10.0.xxxxx.x)

### 🔨编译运行

1.  **克隆仓库:**
    
    ```bash
    git clone https://github.com/3454471560/Pixel-Online
    ```
    
    下载GitHub仓库Release中的 `Pixel-Online-third.zip` 压缩包并解压缩 `thirdparty` 文件夹到`Online.sln`目录。
    
2.  **打开工程:**
    
    使用 Visual Studio 2022 打开根目录下的 `Online.sln`。
    
3.  **配置环境:**
    
    确保构建配置设为`Release` (x64)或`Debug`(x64)。
    
4.  **生成硬编码资源:**
    
    右键项目Bin2C选择重新生成，右键`Asset`项目重新生成，确保将`Asset\Generated`目录下的`.c`字节数据文件包含入项目。
    
5. **点击运行:**

   所有动态库、三方库、项目库、配置文件、场景文件、动画文件自动复制到项目输出目录下，右键解决方案选择要运行的项目（客户端/服务端/瓦皮编辑器/硬编码工具）F5点击运行。
